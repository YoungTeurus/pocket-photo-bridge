# Pocket Photo Bridge MVP 1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline.

**Goal:** Receive a single camera-selected JPEG through Sony's evidenced smartphone push service, preview it, and save it to Gallery; deliver diagnostics and a downloadable APK.

**Architecture:** A pure Kotlin `sony` module owns bounded SOAP/XML parsing and an injectable HTTP transport. The Android `app` owns foreground Wi-Fi attachment, per-Network HTTP, private temporary photos, preview and MediaStore. Manual association through Android Settings lets Android retain credentials without the app collecting passwords or QR data.

**Tech Stack:** Kotlin 2.2.21, AGP 8.13.2, Gradle 8.13, Java 17 bytecode, Android 10+ (API 29), native Android views, JUnit 4.13.2.

**Spec:** `docs/CODEX_PROMPT.md`, `docs/architecture.md`, Issue #1, and the user's implementation request.

## Global Constraints

- No full-library or latest-photo fallback; browse only PushRoot and its descendants.
- No Xiaomi, sign-in, server, cloud upload, background polling or app-owned credentials.
- Camera connections must use the selected Wi-Fi Network, never the default internet route.
- Diagnostic exports contain only predefined stages, numeric counts/statuses and error categories.
- Hardware-level selected-photo and original-quality success remains unverified until the tablet test.

## Review Focus

- Wrong camera mode must stop, never switch to PhotoRoot/PTP.
- Malformed XML, DTDs and off-camera resource URLs must be rejected.
- Paging loops, multiple selections and thumbnail-only responses must not yield an arbitrary photo.
- Interrupted/truncated downloads must remove temporary files and avoid successful TransferEnd.
- Wi-Fi loss, lifecycle exit and Gallery failures must release resources without publishing partial photos.
